# 战斗研究的证据与结论规范

## 证据等级

| 等级 | 定义 | 可以支持的结论 |
| --- | --- | --- |
| E1 | 当前版本原始资源、IL2CPP 字段/签名或运行时代码 | 对象结构、字段访问、控制流和调用顺序 |
| E2 | 可重复运行时探针或内存采样 | 实际分支、参数、状态变化和动态目标 |
| E3 | 可复现游戏内数值、逐帧录像或 UI 快照 | 外部行为、时点和公式结果 |
| E4 | AKEDB、技能文本、现有 Endaxis 或社区资料 | 检索线索和待验证假设 |

E4 不能单独把结论提升为游戏事实。E1 也不总能证明动态行为，例如虚调用目标、IFix 热补丁
或事件监听顺序仍可能需要 E2。

## 结论状态

- **已确认**：控制流或公式有 E1/E2 证据，并由独立样本交叉检查。
- **行为确认**：E3 可稳定复现，但内部实现尚未定位。
- **高可信推导**：多项证据一致，仍有一个关键动态边界未直接观测。
- **假设**：用于设计下一次实验，不得进入生成器或模拟器事实层。
- **已否定**：曾经的假设被反例或更直接证据推翻，保留原因避免重复踩坑。

## 闭环条件

一个字段可以进入自动生成器前，至少要回答：

1. 原始数据从哪里读取，版本与对象身份如何确定；
2. 运行时由哪个方法解释该字段；
3. 它与其他候选字段发生冲突时如何选择；
4. 时间边界是否包含端点，单位和舍入规则是什么；
5. 状态、形态、天赋、潜能和技能等级是否会修改它；
6. 至少两个不同技能样本是否遵守同一规则；
7. 游戏内或运行时观测是否与推导一致。

只满足“生成值碰巧与旧 TS 一样”不构成闭环。

## 记录模板

每项专题结论应记录：

```text

状态：已确认 / 行为确认 / 高可信推导 / 假设 / 已否定
客户端版本：
配置身份：

关键 RVA / token / 字段偏移：
输入样本：
控制流或公式：
外部验证：
反例与适用边界：
尚未确认：

```

## 大型运行时快照

`combat-runtime-dumps/1.4.4/IL2CPP_GameAssembly.runtime.bin` 是按虚拟 RVA 排布的完整运行时
模块快照，不是普通磁盘 PE。其用途是离线提取已知 RVA 周围代码、比较方法入口、查找常量
和扩展调用图，避免为了每个新问题反复启动游戏。

使用限制：

- 必须连同 JSON 中的模块大小、区域权限和布局信息解释；
- 地址要转换为 RVA，不能沿用采样进程的绝对地址；
- 间接调用、虚调用、委托和 IFix 跳板仍可能需要运行时探针；
- 不通过相邻字节线性延伸猜测函数边界，应做可达控制流分析；
- 原始快照不提交 Git，只提交哈希、分析工具和可重建报告。
